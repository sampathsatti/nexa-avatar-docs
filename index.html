1. The shape of the system

Three parties, and the key point is that two of them never talk to each other. ElevenLabs runs the conversation — speech-to-text, the LLM, and text-to-speech. Anam only renders video: it receives raw PCM and returns a face that mouths it. The browser is the bridge, and every frame of agent speech passes through it twice — once toward the speakers, once toward Anam.

2. Session bootstrap

The browser never sees the Anam API key. It calls a Firebase Function, which mints a short-lived session token and returns only that. 

POST /api/anamStartSession          → Firebase Function (anamStartSession)
  POST https://api.anam.ai/v1/auth/session-token
    Authorization: Bearer <ANAM_API_KEY>        // server-side only
    { clientLabel, personaConfig: {
        name: "Jordan", avatarId, voiceId,
        disableBrains: true,                     // ← we supply the words
        enableAudioPassthrough: true,            // ← and the audio
        maxSessionLengthSeconds: 600 } }
  ← { sessionToken }                             // JWT, type: audio_passthrough
← { sessionToken }
The two flags are the whole trick. Passing a stored personaId instead returns a token of type stateful — bound to that persona's own LLM and voice. The avatar then holds its own conversation and has no reason to mouth your audio. Requesting an ephemeral persona with these flags returns type audio_passthrough, where the avatar renders exactly the PCM you push. You can confirm which you got by decoding the JWT's type claim.

3. The audio pipeline

Agent speech — the outbound half

Each ElevenLabs audio event carries base64 PCM16 at 16 kHz. On arrival:

  1. Decode base64 → Uint8Array.
  2. Gate the mic — the agent is about to be audible (see §7).
  3. Schedule locally: convert to Float32, append to an AudioContext queue at nextStartTime so frames abut without gaps or overlap.
  4. Send to Anam: the same bytes go to AgentAudioInputStream.sendAudioChunk().

Local playback runs through a GainNode rather than straight to the destination, and that gain starts at 0. The avatar returns the agent's voice already aligned to its video, so it is the only intended audio source; the browser's own copy is a fallback that is switched on only if the avatar produces no audio track within 10 s, or fails to start at all. A failed avatar therefore degrades to plain voice rather than silence.

Silence by default, not silenced afterwards. An earlier version started the gain at 1 and dropped it once the avatar's track appeared. That read as two overlapping voices, because the mute was applied before the AudioContext existed — the avatar reports its track during bring-up, which now happens before the ElevenLabs socket opens — so it landed on a null node and was lost, leaving the gain at its default. Defaulting to 0 removes the ordering dependency entirely.

User speech — the inbound half

getUserMedia with echo cancellation and noise suppression feeds an AudioWorklet that accumulates 1024 samples (~64 ms), converts to Int16, base64-encodes, and emits user_audio_chunk. A worklet is used rather than ScriptProcessorNode to keep the capture quantum small.

4. Turn boundaries

Anam needs to know when an utterance ends, via endSequence(). Choosing the wrong signal is subtly destructive.

SignalResult
Playback queue drains wrong The queue empties between words mid-sentence, so the utterance is cut off after a few frames and the mouth stops early.
No new audio for 700 ms used Rides through inter-word gaps and fires once the turn is genuinely over.
interruption event, or user types used A real boundary — end immediately, drop buffered frames, stop playback.

5. Startup ordering

ElevenLabs begins streaming its greeting the instant its socket opens. Anam needs several seconds of WebRTC negotiation. Connect in the wrong order and the entire greeting arrives before there is a channel to receive it — the avatar simply never moves, and appears seconds after the voice.

Critically, streamToVideoElement() resolves on negotiation, not on the first painted frame. Gating on it is still too early. The real signal is AnamEvent.VIDEO_PLAY_STARTED, backed by a poll on videoWidth > 0 && !paused and a 12 s timeout so a broken avatar can never strand the conversation. 

await startSimli()          // mint token, attach, open agent-audio channel
await anamVisible           // VIDEO_PLAY_STARTED  ── measured ~4.0 s
await rawConv.start()       // only now connect ElevenLabs ── audio at ~5.1 s

Frames that still arrive early are buffered (capped at 400) and flushed in order once the channel opens, so nothing is lost in the race.

6. Front of house: UI states

The widget is a docked panel: an inset avatar video with the mic as a pill over it, a tagline, two CTAs, the transcript, and a composer. One control surface carries the live state — the mic pill's colour and label.

Connecting…—Minting the Anam session.

listeningblue · “Listening…”Mic open, agent silent.

7. The modality contract

Voice and typing are two doors into one conversation. The rules:

SituationBehaviourWhy
Avatar speech Only ever ElevenLabs agent audio. Nothing else is fed to the lip-sync channel, so the avatar cannot voice anything the agent did not say.
User types One bubble on send; ElevenLabs' echo is suppressed. The agent echoes typed input back as a user_transcript, re-cased and re-punctuated — so matching is on a normalised form within a 20 s window, not the exact string.
User speaks Transcript is logged as a chat message. The written history stays complete no matter which modality was used.
User types while Jordan talks Interrupts him. Playback is cancelled, the buffer dropped and the sequence ended, so the answer to the new message does not overlap the old one.
Jordan is audible Mic is gated shut, reopening ~900 ms after speech stops. His voice leaves the speakers; an open mic lets ElevenLabs transcribe him as the user and answer his own words back.
This makes voice half-duplex. You cannot barge in over Jordan by speaking — though typing interrupts instantly. It is the reliable cure for the self-hearing loop; the alternative is trusting the browser's echo cancellation alone, which is worth revisiting if barge-in matters more than the guarantee.

8. Client tools

The agent drives the page through four tools. Each client_tool_call is executed in the browser and answered with a client_tool_result.

ToolEffect
navigate_to_sectionScrolls to a section and pulses it. Closed enum — the agent cannot invent targets.
show_highlight_slideOpens a pre-authored highlight card.
show_quick_replyRenders tappable replies; a tap is treated exactly like typed input.
advance_demo_slideMoves through the demo deck.

Slide and highlight copy is pre-authored in the page rather than generated, so the agent cannot improvise product claims or statistics.

9. Failure modes worth remembering

SymptomActual cause
Mouth never moves Session was stateful, not audio_passthrough — the avatar was running its own brain.
Mouth never moves, correct token ElevenLabs connected first; the whole greeting landed before the agent-audio channel existed.
Mouth moves briefly then stops endSequence() fired when the playback queue drained between words.
Large apparent A/V lag ElevenLabs audio was passed as userProvidedAudioStream — that argument is the microphone input, not the lip-sync channel. Local audio also played a full round-trip ahead of the returned video.
Agent repeats the user Open mic during agent speech, plus exact-string echo matching that missed re-punctuated transcripts.
Avatar's head cropped Container aspect did not match the 3:2 source, so object-fit: cover had something to crop.

10. Why the browser is the bridge

Agent audio makes a visible detour: ElevenLabs → browser → Anam, when it could in principle go server to server. That is deliberate, and the reason is specific rather than general.

Anam's AgentAudioInputStream is constructed from the signalling connection of the session that opened the peer connection. A server cannot push audio into a session the browser owns. Moving the bridge server-side therefore means the server owns the Anam session — at which point the video arrives there too, and reaching the browser needs an SFU to re-broadcast it. That is new infrastructure, not a relocated hop.

It also costs latency where it is felt most. Today the microphone path is browser → ElevenLabs, one leg. A server bridge makes it browser → server → ElevenLabs in both directions, adding two legs to the turn-taking loop — the delay users read as sluggishness.

A server bridge would…Assessment
Centralise logging and moderation of the audio streamreal gain
Behave uniformly regardless of client network or CPUreal gain
Keep API keys off the clientalready true tokens are minted server-side; the key never reaches the browser
Remove the browser from the audio pathit cannot the microphone still originates there
Require an SFU and a persistent socket servicenew cost
The server-side model exists as a product. HeyGen's LiveAvatar in LITE mode hosts the ElevenLabs agent connection itself and hands the browser a single merged stream — no local bridge, no fork, no sample-rate bookkeeping. If that architecture is wanted, the move is to adopt it rather than build it. The tradeoff is control: it also dictates its own constraints, including requiring the agent to emit pcm_24000.
